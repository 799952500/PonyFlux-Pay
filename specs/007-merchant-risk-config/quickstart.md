# Quickstart: 商户级风控配置

## 目标

验证商户级风控配置从后台配置、商户自助配置到支付请求实时拦截的完整闭环。

## 前置条件

1. 已完成数据库 schema、migration 和 seed 更新。
2. 已安装演示数据库数据：

```bash
python scripts/install_demo_db.py
```

3. 启动管理后台、收银台服务和管理端前端：

```bash
mvn -B -pl payflow-admin-server spring-boot:run
mvn -B -pl payflow-cashier-server spring-boot:run
cd payflow-admin-client && npm run dev
```

## 验证场景 1：管理员创建平台全商户规则

1. 使用管理员账号登录管理后台。
2. 进入「商户与风控 / 风控配置」。
3. 新增规则：
   - 规则类型：单笔金额限制
   - 归属来源：平台规则
   - 作用范围：所有商户
   - 阈值：500000 分
   - 动作：拒绝
   - 状态：启用
4. 分别使用两个不同商户发起超过阈值的支付请求。
5. 预期：两个商户的请求均被风控拒绝，并产生命中记录。

## 验证场景 2：管理员创建平台定向规则

1. 使用管理员账号新增规则。
2. 作用范围选择「指定商户」，只选择商户 A。
3. 使用商户 A 和商户 B 发起相同特征支付请求。
4. 预期：商户 A 被该规则评估并拦截；商户 B 不受该规则影响。

## 验证场景 3：商户创建自建规则

1. 使用商户 A 账号登录商户端或商户风控入口。
2. 新增自建规则：单笔金额超过 100000 分拒绝。
3. 使用商户 A 发起超过阈值的支付请求。
4. 使用商户 B 发起相同请求。
5. 预期：商户 A 被自建规则拦截；商户 B 不受商户 A 自建规则影响。

## 验证场景 4：水平越权拦截

1. 使用商户 A 的登录态调用商户规则更新接口，尝试更新商户 B 的规则 ID。
2. 使用商户 A 的登录态调用命中记录接口，尝试传入商户 B 的 merchantId。
3. 预期：系统返回无权限或不存在；商户 A 无法查看、修改、启停商户 B 的规则或命中记录。

## 验证场景 5：审计和命中查询

1. 管理员修改一条平台规则的阈值和作用范围。
2. 商户启停一条自建规则。
3. 触发一次风控拦截。
4. 管理员查看规则变更审计和命中记录。
5. 商户查看自己的命中记录。
6. 预期：管理员可见全部；商户仅可见自己相关记录；记录包含规则来源、作用范围、处理结果和脱敏请求摘要。

## 测试命令

后端编译：

```bash
mvn -B -DskipTests compile
```

后端完整测试：

```bash
mvn -B clean package
```

前端构建：

```bash
cd payflow-admin-client && npm run build
```

## Definition of Done 检查

- 管理员平台全商户规则和定向规则均可配置、筛选、启停。
- 商户自建规则只能作用于自己。
- 支付请求只评估当前商户适用规则。
- 风控命中记录与规则变更审计可查询，且权限隔离正确。
- 商户越权访问、修改、启停其他商户规则的尝试 100% 被拒绝。
- 金额阈值全链路使用 Long 分，无浮点比较。
- `docs/CONTRACT_MATRIX.md`、SQL schema、seed、migration 已更新。
- 后端和前端测试通过，覆盖率满足项目要求。
