# Feature Specification: 双端统一主题与 UI 体验优化

**Feature Branch**: `009-dual-theme-ui`
**Created**: 2026-05-22
**Status**: Draft
**Input**: User description: "本次目的主要是收银台和管理页面的UI优化，包含整体的一个协调性和美观性，例如后端系统在主题切换的同时，整体风格也要保持一致，例如清新风格，整体就是清新自然，如果是夜晚的风格，那就是狂放一点。表格的显示是重中之重，表格风格要统一，不能出现不协调、不美观的情况。"

## Clarifications

### Session 2026-05-22

- Q: 用户补充（/speckit-clarify）→ A: 表格展示为本特性重中之重；管理端与收银台凡出现表格/类表格数据展示处，须全站风格统一，禁止不协调、不美观的表格样式
- Q: 管理端表格统一策略（单一规范 vs 标准/紧凑变种）→ A: 采用「标准 + 紧凑」两套表格密度规范，各自内部 100% 统一；用户在管理端设置中自行选择偏好，并持久化到本地
- Q: 表格行背景区分方式（斑马纹策略）→ A: 按主题区分——清新类主题使用轻斑马纹，暗夜主题使用略强斑马纹以增强层次；深色行背景/斑马纹不得掩盖或吞没单元格正文、金额、状态标签与操作按钮，须满足可读性底线
- Q: 详情展示形态（弹框 vs 抽屉 vs 跳转页）→ A: 管理端**所有业务详情**均以 `el-dialog` 或 `el-drawer` 呈现，两种形态可按页面需要混用，不限定单一形式；**禁止**为查看详情单独跳转全屏详情路由（旧书签 URL 可重定向回列表并自动打开对应浮层）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理端表格全站风格统一（重中之重）(Priority: P1)

运营人员在管理后台查看订单、商户、对账、路由日志、审计等各类数据列表时，所有表格的表头、行背景、分隔线、悬停态、选中态、空数据态、加载态、分页区必须与当前主题一致，且不同业务页之间不得出现「有的表格带重边框、有的无边框、有的行高不一、有的悬停色突兀」等割裂观感。

**Why this priority**: 用户明确表格为本次 UI 优化的重中之重；管理端以表格为高频载体，表格不协调会直接判定整体改版失败。

**Independent Test**: 在单一主题下连续打开不少于 8 个含表格的管理页面（含宽表、带操作列、带状态标签列）；切换至另一清新预设再切换至暗夜主题，逐页核对表头背景、行高、悬停、斑马纹/分隔、分页与空态是否同一规范；任一页明显「异类」即判失败。

**Acceptance Scenarios**:

1. **Given** 当前为清新类主题, **When** 用户浏览任意含表格列表页, **Then** 表格整体柔和、留白适中，交替行使用轻斑马纹辅助读行，主次列层次清晰，无刺眼高饱和色块或默认组件灰白漏网
2. **Given** 当前为暗夜主题, **When** 用户浏览任意含表格列表页, **Then** 表格对比鲜明、交替行斑马纹略强于清新主题以体现层次，悬停与强调符合「夜晚狂放」性格；所有单元格文字、金额、标签与操作控件相对行背景清晰可辨，无「深色吞字」现象
3. **Given** 用户在同一主题下从订单列表跳转到商户列表再返回, **When** 对比两页表格, **Then** 表头高度、字号、行高、操作列按钮样式、分页位置与样式一致
4. **Given** 表格处于加载中或无数据, **When** 用户停留在该页, **Then** 骨架/空态/提示文案区域仍使用当前主题令牌，不出现与表格主体风格脱节的默认样式
5. **Given** 用户在设置中选择「紧凑」表格密度, **When** 浏览订单、对账等宽表列表页, **Then** 行高与内边距按紧凑规范统一收敛，且与商户列表等标准密度页相比仅密度不同、风格语言相同
6. **Given** 用户已在设置中保存表格密度偏好, **When** 刷新或下次登录管理端, **Then** 自动应用上次所选「标准」或「紧凑」，无需逐页重新设置

---

### User Story 2 - 管理端主题切换后全局风格一致 (Priority: P1)

运营人员在管理后台选择某一主题（如清新薄荷、海蓝、紫罗兰或暗夜）后，登录页、侧栏、顶栏、列表、表单、弹窗、图表等所有可见区域应呈现同一套视觉性格，不出现「部分页面仍是旧配色」或「表格与卡片风格割裂」的情况。

**Why this priority**: 管理端是配置与运营主战场，主题不一致会直接影响专业感与日常使用效率，是本次优化的核心载体。

**Independent Test**: 在管理端依次切换全部可用主题，浏览仪表盘、订单列表、商户配置、系统设置等至少 5 类典型页面，确认配色、圆角、阴影、字号层级、状态色（成功/警告/错误）均随主题统一变化且文字可读。

**Acceptance Scenarios**:

1. **Given** 用户处于管理端任意业务页, **When** 从设置或顶栏切换至「清新」类主题（薄荷/海蓝/紫罗兰）, **Then** 页面背景、卡片、按钮、表格、输入框、标签页均呈现清新、自然、柔和的观感，主色仅作点缀而非压迫性色块
2. **Given** 用户处于管理端任意业务页, **When** 切换至「暗夜」主题, **Then** 整体转为深色基调，对比度与强调色更鲜明、更有张力，符合「夜晚狂放」的性格，且正文与金额等关键信息仍清晰可辨
3. **Given** 用户已选择某主题并刷新浏览器, **When** 重新进入管理端, **Then** 自动恢复上次所选主题，无需重新配置
4. **Given** 用户打开系统设置, **When** 查看外观/显示类配置区, **Then** 可找到与主题并列的「表格密度（标准/紧凑）」选项，修改后全站表格即时生效

### User Story 3 - 收银台与后台设计语言对齐 (Priority: P1)

商户或付款人在收银台完成支付流程时，所见的品牌色、排版、按钮与状态反馈应与 PonyFlux 管理端属于同一产品家族；当用户在不同端之间切换时，不应产生「两个不同产品」的割裂感。

**Why this priority**: 收银台是对外门面，与管理端视觉统一是品牌与信任感的关键。

**Independent Test**: 在同一浏览器会话中先后打开管理端（任选一种清新主题）与收银台支付页，对比主色、圆角、字体气质、成功/失败态展示是否属于同一设计体系；再切换管理端为暗夜主题后对比收银台深色表现（若收银台支持深色）。

**Acceptance Scenarios**:

1. **Given** 管理端使用清新类主题, **When** 用户打开收银台支付页, **Then** 收银台主视觉（头部、金额区、支付按钮、成功/失败提示）体现清新、自然、可信赖的气质，与管理端清新主题同源
2. **Given** 用户习惯夜间操作, **When** 在支持深色的端使用夜间/深色模式, **Then** 收银台深色表现更具张力与对比，与管理端暗夜主题性格一致，而非简单反色
3. **Given** 收银台在移动端或窄屏下展示, **When** 用户完成选支付方式、确认支付、查看结果全流程, **Then** 布局不挤压、不遮挡关键金额与操作按钮，风格与桌面一致

---

### User Story 4 - 跨页面与跨组件的视觉协调 (Priority: P2)

无论管理端还是收银台，列表空状态、加载态、图表、徽章、分页、面包屑等「次要但高频」组件，其颜色与间距应服从当前主题令牌，避免硬编码色块在切换主题后「漏网」。

**Why this priority**: 细节不一致是用户感知「不精致」的主要来源，需在主流程打通后统一收口。

**Independent Test**: 在单一主题下打开含图表的仪表盘、含空列表的查询页、含多步骤表单的配置页，检查加载动画、空状态插画/文案区、ECharts 或同类图表轴线和图例颜色是否与卡片背景协调。

**Acceptance Scenarios**:

1. **Given** 当前为清新类主题, **When** 页面展示图表与数据卡片, **Then** 图表网格线、轴线、Tooltip 背景柔和，不刺眼，与页面背景层次分明
2. **Given** 当前为暗夜主题, **When** 页面展示图表与数据卡片, **Then** 图表使用高对比配色与适度发光/强调效果，体现夜晚主题的张扬感且不损失数据可读性
3. **Given** 列表无数据或接口加载中, **When** 用户停留在该页, **Then** 空状态与加载指示器使用主题色衍生样式，不出现与主题无关的默认灰白块

---

### User Story 5 - 主题切换过程体验流畅 (Priority: P3)

用户切换主题时，界面应即时、平滑地应用新风格，无长时间闪烁、布局跳动或需手动刷新才能生效的页面。

**Why this priority**: 提升主观品质感，但不阻塞核心业务。

**Independent Test**: 在管理端连续快速切换 4 种主题各 3 次，观察是否出现 FOUC（未样式化内容闪烁）、侧栏宽度异常、图表残留旧色等问题。

**Acceptance Scenarios**:

1. **Given** 用户位于任意管理端页面, **When** 点击切换主题, **Then** 1 秒内可见区域完成配色更新，无整页白屏闪烁
2. **Given** 用户切换主题后立刻进行筛选或翻页, **When** 新数据渲染到表格, **Then** 新行仍使用当前主题样式

---

### Edge Cases

- 用户浏览器禁用本地存储时：当次会话仍应用所选主题，刷新后回退至系统默认清新主题，并可在界面给出一次性提示（不阻断操作）
- 用户操作系统开启「高对比度」或「减少动画」辅助功能时：主题仍可用，对比度满足可读性底线，动画可降级为即时切换
- 超长商户名、大金额、多语言文案在收银台窄屏下：主题切换后仍不换行错乱、不遮挡支付主按钮
- 打印或导出 PDF/截图场景（若存在）：以当前屏幕所见配色为准，不要求单独打印主题
- 用户仅使用收银台、从未打开管理端：收银台默认呈现品牌默认可清新主题，无需依赖管理端先验配置
- 宽表横向滚动时：表头与首列（若冻结）在清新/暗夜主题下均保持可读，滚动条样式与主题一致，不出现表头与表体错位或双色表头
- 表格内嵌套标签、开关、链接按钮：颜色与尺寸服从表格行内规范，不撑破行高或造成列对齐错乱
- 用户禁用本地存储时：表格密度与主题一样，当次会话生效，刷新后回退为「标准」密度默认值
- 用户从「紧凑」切回「标准」或反向切换：已打开页面的表格须即时重排，无残留旧行高导致的布局错位
- 暗夜主题下斑马纹与悬停层叠加时：仍须保证正文、链接、状态色标签与图标对比度达标，不得因多层深色叠加导致内容「看不见」
- 清新主题下行内彩色状态标签与轻斑马纹并存时：标签背景不得与行背景融为一片，须保持可识别边界

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 管理端必须提供至少一种「清新自然」性格的主题族（可含多种色相变体，如薄荷、海蓝、紫罗兰），切换后全站主要界面组件（导航、内容区、表格、表单、弹窗、图表）视觉一致
- **FR-002**: 管理端必须提供「暗夜/夜晚」性格的主题，相对清新主题具有更强对比、更鲜明的强调色与更富张力的整体氛围，同时保证正文、标签、金额等关键信息可读
- **FR-003**: 用户选择的管理端主题偏好必须在同浏览器再次访问时自动恢复
- **FR-004**: 收银台必须与 PonyFlux 管理端共享统一的设计语言（色彩体系、圆角与间距尺度、按钮与状态语义），使两端看起来像同一产品
- **FR-005**: 收银台在清新主题下必须传达自然、清爽、可信赖的支付体验；在深色/夜间场景下必须传达更有力量感的视觉性格，与管理端暗夜主题一致
- **FR-006**: 主题切换必须即时作用于当前已打开页面，无需用户手动刷新整个应用
- **FR-007**: 所有面向用户的状态反馈（成功、警告、错误、禁用、加载中）在任意主题下必须可区分且符合无障碍可读性底线（正文与背景对比度达到行业通用的 AA 级要求）
- **FR-008**: 管理端典型业务路径（登录 → 仪表盘 → 列表查询 → 详情/编辑 → 设置）在每种主题下必须完成端到端可走通且无明显样式破损
- **FR-009**: 收银台典型支付路径（进入收银页 → 选择支付方式 → 支付结果）在清新与深色场景下必须完成端到端可走通且核心信息（金额、订单号、状态）始终突出
- **FR-010**: 主题系统必须通过可复用的视觉令牌（颜色、背景、边框、阴影、字号层级）驱动组件，避免零散硬编码导致切换后局部漏改
- **FR-011**: 管理端所有数据列表表格必须遵循统一的表格视觉规范体系，且仅允许「标准」「紧凑」两种密度变种；同一密度下各业务页表头、行、悬停、分页、空态必须完全一致，为本特性最高优先级交付项
- **FR-015**: 管理端须在设置（外观/显示类配置区，与主题配置同级入口）提供「表格密度」选项，供用户在「标准」与「紧凑」之间切换；选择后全站表格即时生效
- **FR-016**: 用户选择的表格密度偏好须保存在浏览器本地，并在下次访问管理端时自动恢复；未配置过的新用户默认使用「标准」密度
- **FR-012**: 表格样式必须由主题令牌驱动；切换清新预设或暗夜主题时，表格须与卡片、表单同步更新，禁止残留上一主题色或浏览器默认表格样式
- **FR-013**: 表格行内元素（状态标签、操作按钮、链接、图标）须限制在统一行高与对齐规则内，不得因单页自定义导致列错位或行高不一致
- **FR-014**: 收银台若存在订单/交易类表格或类表格布局，其表头、行、强调色须与管理端当前主题性格一致；无表格的页面不降低管理端表格规范要求
- **FR-017**: 表格交替行背景（斑马纹）须随当前主题性格变化：清新类主题为轻斑马纹，暗夜主题为略强斑马纹；两种密度（标准/紧凑）下均适用同一斑马纹规则
- **FR-018**: 暗夜主题表格的深色行背景、斑马纹与悬停层不得降低单元格内容的可辨识度；正文、金额、链接、状态标签与行内按钮相对其直接背景须满足无障碍 AA 级对比度，禁止出现内容被深色「淹没」的情况
- **FR-019**: 管理端查看业务实体详情（订单、商户、退款、路由决策、费率规则等）须使用 `el-dialog` 或 `el-drawer` 浮层展示，可按信息密度在两种形态间自由选择，不得为「仅查看」场景新增全屏详情页；历史详情 URL 须重定向至对应列表并自动打开浮层

### Key Entities

- **主题（Theme）**: 一套完整的视觉性格定义，包含主色、背景层级、文本色、强调色、组件状态色及图表配色策略；分为「清新族」与「暗夜族」两大性格
- **主题预设（Theme Preset）**: 清新族下的具体色相变体（用户可择一），共享清新自然气质但主色不同
- **视觉令牌（Design Token）**: 抽象命名的一组样式变量（如页面背景、卡片背景、主操作色、表头背景、行悬停色），供各页面与组件引用
- **表格规范（Table Style Contract）**: 管理端（及收银台适用处）共用的表格视觉约定，涵盖表头、行、分隔、交替行斑马纹（清新轻/暗夜略强）、交互态、分页与空态的最小一致集；在视觉上分「标准密度」「紧凑密度」两套，共享同一主题性格与组件语言
- **用户主题偏好（User Theme Preference）**: 用户在某一端最后一次选择的主题标识，保存在浏览器本地，用于下次访问恢复
- **用户表格密度偏好（User Table Density Preference）**: 用户在管理端设置中选择的「标准」或「紧凑」，保存在浏览器本地，作用于全站数据列表表格

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在可用性走查中，至少 90% 的参评者能在 10 秒内指出管理端当前属于「清新」或「夜晚」哪一种性格，且两种性格的描述与管理端实际观感一致
- **SC-002**: 管理端单主题切换后，95% 以上的抽检页面（不少于 12 个不同路由类型）在 1 秒内完成可见样式更新，无需整页刷新
- **SC-003**: 收银台与管理端并排展示时，至少 85% 的参评者认为「属于同一品牌/同一产品」，而非两个独立系统
- **SC-004**: 在清新与暗夜两种性格下，各抽取不少于 20 处文本/背景组合进行对比度抽检，100% 满足 AA 级可读性要求
- **SC-005**: 收银台支付主路径（进入 → 支付 → 结果）在移动端视口（宽度 ≤ 390px）下，关键操作可在 3 次点击内完成，且全程无因主题导致的遮挡或不可点击控件
- **SC-006**: 主题相关缺陷（漏色、对比度不足、切换后残留旧样式）在发布前回归清单中为零阻塞项
- **SC-007**: 管理端表格专项走查：抽检不少于 10 个含表格路由，100% 符合统一表格规范；参评者中至少 90% 认为「各页表格风格一致、美观」
- **SC-008**: 主题切换后表格专项抽检：对上述路由在 4 种管理端主题各切换 1 次，表格区域 1 秒内完成样式更新且无残留旧主题色的比例为 100%
- **SC-009**: 在「标准」与「紧凑」两种密度下各抽检不少于 5 个含表格路由，同一密度内各页表格风格一致性通过率 100%；切换密度后 1 秒内全站表格完成行高更新
- **SC-010**: 暗夜主题表格可读性专项：在含斑马纹与悬停态的表格中抽检不少于 30 个单元格（覆盖正文、金额、状态标签、操作按钮），相对其直接背景的对比度 100% 满足 AA 级；走查中「深色掩盖内容」类缺陷为零

## Assumptions

- 范围限定为 **管理端 Web 应用** 与 **收银台 Web 应用** 的用户界面，不包含支付渠道 SDK、原生 App 或邮件模板
- 管理端继续支持多种清新色相预设 + 一种暗夜预设；清新预设共享「清新自然」性格，差异主要体现在主色与点缀色
- 收银台至少完整支持与管理端一致的清新默认体验；深色/夜间体验与管理端暗夜性格对齐（若收银台暂不暴露多预设切换，仍须视觉同源）
- 主题偏好仅存于用户浏览器本地，不要求跨设备同步，也不依赖后端用户配置接口
- 不改变现有业务功能、权限与路由，仅优化视觉与主题一致性
- 图标与 Logo 资产可沿用现有品牌资源，必要时仅调整在深色背景下的可见性
- 国际化文案长度变化已纳入布局弹性考虑，不单独为本特性扩展语言包
- 表格规范优先覆盖管理端全部数据列表表格场景；收银台以支付主流程为主，表格为次要但须与管理端同源
- 表格密度为管理端用户级本地偏好（与主题偏好类似），不要求按商户或角色区分，也不依赖后端存储
- 「紧凑」仅收敛行高与单元格内边距（及与之匹配的表头高度），不单独降低正文字号，以保证可读性底线
- 清新类主题的斑马纹对比度刻意低于暗夜，以符合「清新自然」；暗夜斑马纹可更强，但须服从 FR-018 的内容不可淹没约束
