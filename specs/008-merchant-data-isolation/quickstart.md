# Quickstart: 商户数据隔离治理

## 目标

验证后台系统在交给商户管理员运维时，商户之间的数据不会混淆；同时确认全局配置仍保持平台共享能力。

## 前置条件

1. 已准备至少两个商户及各自订单、支付、退款、渠道账号、路由、对账和风控数据。
2. 已准备至少一个商户管理员账号，并限制到其中一个商户。
3. 已准备一个系统管理员账号。
4. Demo 数据库可通过以下命令重置：

```bash
python scripts/install_demo_db.py
python scripts/verify_admin_password.py
```

## 验证路径

### 1. 商户管理员隔离验证

1. 使用商户 A 管理员登录后台。
2. 查看订单、支付、退款、渠道配置、路由、对账、风控、统计看板和导出入口。
3. 确认所有列表、统计和导出结果只包含商户 A。
4. 尝试使用商户 B 的资源标识访问详情、编辑、审核、退款或批量操作。
5. 确认系统拒绝访问或返回无可操作数据，且不泄露商户 B 信息。

### 2. 系统管理员治理验证

1. 使用系统管理员登录后台。
2. 打开 **数据隔离治理** 页面（`/admin/data-isolation`，菜单种子已配置）。
3. 查看数据隔离检查结果；可点击 **执行扫描** 刷新检查项。
4. 按商户、风险等级、整改状态筛选检查项。
5. 查看商户级数据时确认每条结果均可识别商户归属。
6. 查看全局配置时确认其不被强制绑定到单一商户。

### 3. 存量数据缺口验证

1. 查找缺少商户归属或归属无法自动判断的数据。
2. 确认这些数据进入“需人工确认”或限制访问状态。
3. 使用普通商户管理员确认无法访问这些待确认数据。
4. 由系统管理员补充归属、豁免或标记处理结果。

### 4. 全局配置验证

1. 查看公共字典、基础支付方式、菜单模板、平台通用规则等全局数据。
2. 确认商户管理员只能看到允许的共享信息或脱敏摘要。
3. 确认包含商户专属密钥、账号、费率、回调地址的数据被视为商户级数据。

### 5. E2E 与日志闭环

涉及后台页面、跨服务查询、支付链路或对账链路时，按影响范围执行 Playwright/Playwright CLI 验证，并同步观察相关服务日志。

```bash
cd payflow-admin-client && npx playwright test
cd payflow-cashier-client && npx playwright test
```

验证期间需关注：

- 后台服务是否出现 ERROR 或异常堆栈
- 是否出现 SQL 错误、权限错误或接口契约错误
- 是否出现跨商户数据混入
- 是否出现导出或批量操作绕过隔离

## 通过标准

- 商户管理员跨商户读取或修改阻断率达到 100%。
- 所有纳入治理的数据类别都完成商户级、全局级、系统审计或待人工确认分类。
- 至少两个商户样本下，列表、详情、统计、导出、批量和异步场景均无跨商户数据混入。
- 待人工确认数据在处理完成前不会暴露给普通商户管理员。
- 全局配置仍可正常共享，且不泄露商户专属敏感信息。
- Playwright 验证通过，相关后台日志无阻断错误。
