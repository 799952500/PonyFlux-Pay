## New Entities

### JwtBlacklist (Redis)

```
Key:   jwt:blacklist:{jti}
Type:  String
Value: "logout" | "force_logout" | "password_change"
TTL:   Token 剩余有效期 (exp - iat 秒数)
```

**Fields in JWT payload (new)**:
| Field | Type | Source | Description |
|-------|------|--------|-------------|
| `jti` | String (UUID) | `UUID.randomUUID().toString()` | Token 唯一标识 |

**Lifecycle**:
1. 用户登录 → 生成 JWT 时添加 `jti` 声明
2. 用户登出 → `POST /auth/logout` → Redis `SET jwt:blacklist:{jti} "logout" EX {remaining_seconds}`
3. 每次 API 请求 → `JwtInterceptor` 解析 jti → `Redis EXISTS jwt:blacklist:{jti}` → 存在则 401
4. TTL 到期 → Redis 自动删除 → Token 自然失效（与 JWT exp 同步）

**Edge case**: Redis 不可用 → fail-close：拒绝所有请求（安全优于可用性）。

## Entity Changes

### cashier_merchants.password

```
Before: VARCHAR(128), stores MD5 hex (32 chars)
After:  VARCHAR(256), stores bcrypt ($2a$..., 60 chars)
```

**Migration**: 无 DDL 变更（字段长度足够）。应用层兼容逻辑：
1. 取数据库中密码字段
2. 尝试 `BCryptPasswordEncoder.matches(plainText, storedPassword)` → 成功则登录
3. 若失败且 storedPassword 长度为 32 字符 → 尝试 MD5 比对 → 成功则 `BCryptPasswordEncoder.encode(plainText)` 写回
4. 若均失败 → 密码错误
