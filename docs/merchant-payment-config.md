# 商户支付配置与实付路由（运营说明）

## 配置入口

在 **商户与风控 → 商户管理** 中，点击某商户行的 **「支付配置」**，维护该商户的收银能力。侧栏原 **「路由与费率 → 支付路由」** 已下线，旧链接 `/admin/channel-routes` 会跳转到商户管理。

## 两套数据各自做什么

| 层级 | 数据位置 | 作用 |
|------|----------|------|
| **展示** | 管理库 `merchant_payment_routes` | 收银台页展示哪些 **支付方式**，以及在 **PC / H5 / APP** 哪些终端可见 |
| **实付** | 收银库 `cashier_channel_merchant_routes` | 用户确认支付后，系统按 **渠道账户** 与 **优先级** 选择实际收款账号 |

保存商户支付配置后，管理端会 **自动同步** 到收银库实付路由，并（在启用 Redis 时）通知收银台刷新内存路由表。

## 运营填写要点

1. **支付方式**：决定顾客在收银页看到「微信 App / H5 / 支付宝 …」等选项。
2. **收款账号**：须与所选支付方式 **同一渠道**；同步到收银台时按账号编码 `account_code` 匹配收银库 `cashier_channel_accounts`。
3. **终端（PC/H5/APP）**：仅影响展示，不参与实付账号选择。
4. **优先级**：同一商户、同一收银账户多条配置时，取 **最高优先级** 写入实付路由。

若管理端账号编码与收银库不一致，同步会回退为该渠道下第一个 **ENABLED** 账户并写 WARN 日志，请在 **渠道与账户 → 支付账号** 与收银库账户编码对齐。

## 与管理端「支付路由」历史页的区别

- **商户支付配置**：支付方式 + 终端 + 账号，驱动收银 **展示** 并 **推送** 实付路由。
- **原支付路由页**（`admin_channel_routes`）：仅渠道 + 账号台账，**不再作为运营入口**，且不会单独驱动收银台。

## 技术参考

- 同步实现：`MerchantCashierRouteSyncServiceImpl`
- 保存钩子：`MerchantPaymentRouteServiceImpl`（提交 admin 事务后同步）
- 收银台选账号：`PayChannelAccountRegistry` / `PaymentServiceImpl.routeToAccount`
